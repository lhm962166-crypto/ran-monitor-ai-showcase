# 系统架构与数据流

本图描述本地演示和单机部署时的数据路径。演示模式通过 `demo.py` 生成合成 JSONL，并把数据、模型与 SQLite 文件放在独立临时目录；真实训练由使用者通过 `RAN_MONITOR_DATA_PATH` 提供数据。

```mermaid
flowchart LR
    A[合成生成器或用户 JSON] --> B[解析与输入校验<br/>features.py]
    B --> C[KPI 时序特征]
    C --> D[异常检测模型<br/>engine.py]
    D --> E{校准阈值判定}
    E -->|正常| F[检测结果与证据]
    E -->|异常| G[根因候选分类]
    E -->|异常| H[KPI 影响规则生成 P1–P4]
    G --> I[不确定性与复核提示]
    G -. 仅供参考 .-> J[原型候选排序]
    C -. 影子诊断 .-> K[结构关系偏离]
    H --> L[告警窗口与持续事件]
    I --> L
    F --> M[Streamlit 看板 / CLI]
    L --> M
    M --> N[SQLite 告警、状态与审计]
    M --> O[CSV / JSON / 离线 HTML]
    M --> P[回放与漂移观察]

    Q[训练 JSONL] --> R[来源、身份与时间审计<br/>data_audit.py]
    R --> S[事件 ID 与同流时间重叠分组<br/>train.py]
    S --> T[前向切分或分组留出]
    T --> U[训练区 / 验证区 / 测试区]
    U --> V[检测器与根因分类器]
    U --> W[验证集阈值和候选校准]
    U --> X[留出集诊断]
    V --> Y[模型快照]
    W --> Y
    X --> Z[晋级门禁<br/>证据不足时 hold]
```

## 关键边界

- 异常分数来自 KPI 特征；故障标签、事件标识和上下文标签不作为检测/根因特征。
- 阈值与校准只从训练流程中的验证分区确定。最终泛化结论需要开发过程未使用的冻结测试数据。
- 根因模型产生候选，不给出因果结论。P1–P4 由观测到的 KPI 影响规则计算。
- 原型排序与结构偏离保留为影子诊断，不参与告警判定。
- 合成演示只验证软件路径。生产晋级还需要有许可的真实标注数据、实体/事件身份和按时间前向评测。
