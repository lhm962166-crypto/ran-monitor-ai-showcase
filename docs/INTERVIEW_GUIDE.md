# 面试讲解提纲

这份提纲区分历史开发结果和仍属影子模式的机制。文中 690 窗口实验来自本机 TelecomTS 子集；数据和切分未随仓库发布，干净克隆无法复现这些指标。面试时应称它们为历史开发结果，不要说成当前发布版或生产成绩。

## 90 秒项目介绍

我做了一个面向 5G RAN KPI 窗口的本地异常监测平台。输入是 128 个采样点、16 项 KPI，先由 XGBoost 做异常门控，再对异常给出原因候选。告警级别由可观察 KPI 影响决定，与原因预测解耦。系统支持中文看板、离线批量检测、阈值校准、窗口回放和 SQLite 处置审计。

我重点处理了时间序列评估里的泄漏问题：有事件 ID 时，同一事件的窗口会连成一组；有流 ID 时，时间重叠窗口也会连成一组，二者通过传递关系合并。满足身份与时间覆盖条件时采用前向切分，并检查整个组的起止时间；证据不足时保留组边界做分层留出。根因分类训练按类别和独立组平衡样本权重，交叉验证只在训练组内进行。演示使用项目生成的合成数据，便于干净克隆验证界面与告警路径；它不代表真实网络效果。旧的 690 窗口本地子集没有基站/事件 ID，不能证明现网或未来基站泛化。

## 最值得讲的工程决策

| 面试追问 | 可核验的回答 |
|---|---|
| 为什么用两阶段模型？ | 正常窗口不需要进入故障分类器，检测与原因排序的指标分开统计。原始分类分数仍保留；温度缩放只作为实验列展示，APS 候选集合不被包装成覆盖保证，因为验证故障数和独立时间组都不足。 |
| 如何避免事件与相邻窗口泄漏？ | 同一显式事件 ID 的窗口先连接；同一流中时间相交的窗口也连接；通过并查集取传递闭包后再划分。前向划分同时检查组最早开始和最晚结束时间，跨越切点的组不能被拆开。旧数据缺身份时仍不能证明事件独立。指标同时报告 ROC-AUC 与 AP。 |
| 为什么按类别和时间组加权？ | 训练集里的 Congestion 只有 9 个窗口、3 个不重叠时间组。逐窗口等权会让重叠窗口贡献重复权重；组内等质量、类别等总量的训练组交叉验证 Macro-F1 从 0.527 到 0.595。类别支持仍少，而且缺少事件 ID，不能证明组间事件独立；这是有边界的实验结果，不代表线上收益。 |
| 阈值怎么定？ | 用验证集校准目标召回率或误报率，再固定阈值评估留出测试集。测试标签不用于选阈值；若目标不可达，报告会说明回退。 |
| 为什么不直接加大语言模型？ | 实时告警需要稳定、可测的延迟和决策边界。检测路径不调用 LLM；若以后加文本摘要，应放到离线辅助环节，且不改变模型判定。KAC 的近期实现也将 LLM 文本摘要放在离线生成，在线检测保持轻量。 |
| 怎么判断漂移监测有用？ | 固定验证分数分布作参照，分别测稳定流误报和受控均值/扩散/异常激增下的发现率与延迟。模拟只验证监测算法行为，不等同于现场故障检出率。 |
| 历史开发模型最大的错误是什么？ | 旧开发留出上的两阶段端到端故障 Macro-F1 为 0.584，低于仅在已检出的异常上评价原因分类的 Macro-F1 0.634。Mobility 只有 4 个测试窗口，其中 2 个被漏检、1 个误分为 Equipment、1 个正确；样本太少，下一步先补独立移动性事件和实体身份，再做训练策略实验。 |
| 结构通道带来多少收益？ | 留一故障类别实验在同一个 5% 验证误报预算下进行；小样本上融合帮助了 Congestion 和 Interference，但 Interference 测试误报为 5.5%，Mobility 仍全部漏检，因此继续作为影子通道，不能声称稳定收益。 |
| 为什么不采用温度缩放？ | 当前只有 22 个 APS 校准窗口和 5 个时间组。类别加权后，温度缩放使原因 Brier 从 0.492 变为 0.603，ECE 从 0.162 变为 0.236；程序保留实验值并要求复核，不把它用于生产概率声明。 |
| 能否上线自动重训？ | 现在不行。评分分布变化不等于概念或标签变化；旧演示数据缺少来源、事件身份和足够的前向标签。先由人工检查、补齐标注，再比较候选模型并走晋级评审。 |
| 为什么晋级门禁还检查评估协议？ | 数据有 cell/event ID 只说明有机会做前向评测，不证明当前测试集来自未来。门禁把数据适用条件与实际 `forward_time_holdout` 结果分开，防止随机分组成绩被误读成未来泛化证据。 |

## 可直接复现的证据

```powershell
python -m ran_monitor_ai demo
python -m unittest discover -s tests -v
```

当前测试套件由固定种子的项目合成数据驱动，完整执行训练、CLI 检测和 Streamlit AppTest，不要求 TelecomTS。发布候选的准确测试总数应以实际运行结果为准；Windows 受限环境运行 AppTest 时需要允许本地 loopback socket。延迟与内存受机器和依赖版本影响，对外展示前应说明测量环境。`evaluate`、`compare-detectors`、`verify_reproducibility.py` 与 `promotion-check` 需要通过 `RAN_MONITOR_DATA_PATH` 提供可训练数据；合成演示不能满足生产晋级门槛。

准备面试演示时，从 `python -m ran_monitor_ai demo` 启动实际看板，依次检查实时检测、告警中心、窗口回放和导出。展示截图应来自浏览器中的真实页面，并在 README 标明数据为合成数据。

## 简历项目描述草稿

> 独立实现中文 5G RAN KPI 异常监测平台：构建 XGBoost 两阶段异常检测/故障分类、验证集阈值校准与时间重叠组留出评测，集成 AP/ROC-AUC 及分组区间、SQLite 告警审计、批量 CLI/JSON/CSV/离线 HTML、漂移观察和晋级证据门禁。历史本地验证基于 690 个 TelecomTS 窗口；样本缺少基站/事件 ID，且数据未随代码公开，不能作为可复现或现网成绩。

若确实能保留并展示对应数据快照，可补充历史固定开发集异常检测 F1 0.927、组 bootstrap 95% CI 0.703–0.973；必须同时说明测试集只有 151 个窗口，指标无法通过仓库复现，且组间事件独立性无法证明。这不是最终泛化成绩，也不能写成生产效果。

本项目的功能设计参考了公开 RAN 异常检测工作，数据来自 TelecomTS 子集；仓库的 [数据来源说明](../DATA_SOURCES.md) 和 README 保留了出处。若学校或招聘方要求披露 AI 辅助开发，请按要求说明。
